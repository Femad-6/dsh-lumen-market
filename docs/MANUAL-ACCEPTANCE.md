# 实机升级与取消验收

使用单独的测试 profile 和可丢弃的测试插件；不要拿日常 profile 做失败注入。记录 DSH、Node、市场版本及安装来源，并将 package.json、pnpm-lock.yaml 与 bundles 顺序的操作前副本保存到独立位置。

1. 安装测试插件的旧 npm 版本，并保持禁用。打开已安装页，确认本地列表能先显示，后台更新检查结束后出现新版；点击重新检查确认可取得新状态。
2. 请求升级预览，核对当前版本与目标确切版本。确认升级后观察下载、应用或待重启阶段。核对磁盘版本、bundles 顺序和禁用状态，刷新页面确认待重启提醒仍存在。
3. 在测试 profile 中制造一次可控网络失败。确认界面显示失败分类和诊断；比较操作前后的 package.json 与 pnpm-lock.yaml，确认官方管理器恢复文件，市场没有报告成功。
4. 对另一次测试安装，在下载期间点击取消。等待最终取消结果，再比较 profile 文件；断开客户端请求不能代替取消确认。若已进入应用阶段，应显示无法取消并等待实际结果。
5. 遇到 pendingBuilds 时，仅核对提示；脚本授权必须在官方流程中另行明确决定。市场不得自动允许脚本或写入兼容性豁免。
6. 正常退出并重新启动测试宿主，确认待重启提醒清空。记录失败、取消过晚和重启前后的观察，附脱敏截图。

以上是实机验收流程，不是已完成记录。自动化集成测试使用模拟安装器，不替代这里的官方桌面安装、升级或文件恢复验证。结束后保留测试资料；需要清理目录时由使用者手动处理。

## 诊断关闭与卸载

1. 点击「诊断」，确认独立面板可滚动；点击「关闭诊断」后内容消失，再次点击可重开。安装/卸载结果不能被诊断操作覆盖。
2. 在测试 profile 的已安装卡片点击「卸载」，核对插件名、来源和版本；取消后依赖和选择状态不变。受保护内置项的卸载按钮应禁用。
3. 在测试 profile 确认卸载，成功后列表不再显示该项，打开的旧详情关闭。检查官方失败（例如 stop-profile、bundle-in-use）时展示原因，不误报成功。
4. 未配置 removeBundle 的宿主禁用卸载。确认前后修改测试目标或切换 profile，应拒绝旧预览。

本次自动化仅覆盖模拟卸载，不是对真实桌面插件执行卸载的验收记录。

## 长列表卸载入口

滚动到已安装列表下方，分别从卡片和详情点击「卸载」，确认区应自动进入视野且获得焦点。未安装详情不显示卸载，受保护详情按钮禁用。模拟失败时错误提示应可见、插件保留；确认成功后列表刷新。离线复现可用 `npm run preview` 并打开 `http://127.0.0.1:19408/?layout=installed-long`。

操作结束后点击「关闭提示」，确认操作结果、警告和诊断同时收起，列表保持刷新后的状态，重启提醒仍保留；卸载结果的诊断标题应为「卸载诊断」。

## 持久化发现缓存

1. 成功查询后重启测试宿主，确认恢复相同的关键词、来源、排序和页码，并先显示缓存及保存时间。
2. 慢查询时原列表保留；模拟限流时旧列表继续显示，错误仍可见；新成功结果再替换列表。
3. 改用没有缓存的关键词或排序，不得将其它查询结果标作该查询。成功空结果应覆盖旧快照。
4. 缓存中的插件已安装时，从发现结果隐藏。确认缓存没有 Token，损坏缓存不阻断页面；无法保存时显示提示。

## 21项分页

宽屏下打开结果充足的发现列表，应为每页21项、三列七行。安装若干前排候选后重新查询，应从后续结果补足；逐页检查不重复、不遗漏。全部来源每页总数不超过21。末页不足时按实际条数显示并禁用下一页。仅可安装筛选可能减少当页可见卡片。
